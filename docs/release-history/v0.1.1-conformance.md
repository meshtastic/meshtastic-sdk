## Environment note (v0.1.1)

Run against the **meshtastic-mcp simulated TCP device** (`replay_start`, meshcon synthetic
mesh, 25 nodes, `127.0.0.1:4403`) at the maintainer's direction — no bench radio was
reachable (no serial device; no `meshtastic.local`), and the SDK has no published consumers.

The two FAILs were A/B'd: the **released v0.1.0 CLI produces identical results against the
same simulator** (cs1 PASS 639 ms / cs2 FAIL "did not reach terminal state" / cs3 PASS /
cs5 PASS 27 nodes / cs6 FAIL "Channel was closed" 9 ms). Root causes are simulator
limitations, not candidate regressions:

- **cs2** — the simulator does not emit routing ACKs for app-originated sends, so a
  broadcast never reaches a terminal state.
- **cs6** — raw back-to-back TCP connects to the simulator both succeed with a ~300 ms gap;
  the CLI's instant (≤14 ms) reconnect races the simulator's single-client teardown.

cs4/cs7 skipped (no `--peer-node`; the simulator would not answer traceroute/DM either).
